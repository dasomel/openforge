# Legacy Evidence Catalog

`portfolio/legacy-evidence-catalog.json` is the committed inventory of evidence that already exists across the scoped OSS repositories. It references historical paths in place; it does not move, rewrite, or normalize the source artifacts. The `portfolio/` location keeps the catalog beside the existing portfolio registries and makes its portfolio-wide scope explicit.

Each entry uses these fields: `repository`, `path`, `evidence_date`, `evidence_class`, `evidence_strength`, `environment_scope`, `metrics_or_facts`, `limitations`, `future_paper_use`, `privacy_review`, and `availability`. Classes are `verification-quality`, `deployment-reproducibility`, `reliability-recovery`, `runtime-performance`, `agent-assisted-engineering`, `release-adoption-evolution`, and `architecture-requirements`. Strength is `measured`, `observed`, `derived`, or `contextual`; environment is `local-test`, `ci`, `simulation`, `live-test`, or `unknown`; privacy review is `public-ok`, `secret-check-required`, or `exclude`. Availability is `committed` when the path is tracked in its repository, `local-only` when it exists in the scanned working tree but git does not track it, and `unknown` when the scanned root is not a git repository at all; it is read from `git ls-files`, once per repository. A `local-only` entry is kept rather than dropped -- some are real measurements, such as committed-nowhere load-test results -- but it is not reachable from a clone and its `limitations` says so, because preserving it means deliberately committing or archiving it. Unavailable repositories are listed separately in `pending_repositories` with `not-scanned` status.

Regenerate a repository candidate list with `python3 templates/scripts/inventory-legacy-evidence.py --repo PATH --repository SLUG`; use `--refresh --catalog portfolio/legacy-evidence-catalog.json` to replace that repository's entries after review. Validate the committed catalog with `python3 templates/scripts/inventory-legacy-evidence.py --validate`. Discovery is deterministic and conservative: `measured` requires a recognized count, unit-bearing duration/resource/percentage, or known numeric field in a structured record. Other machine records are `observed`; prose and design narratives are `contextual`. Dates come only from ISO dates in paths/filenames or explicit structured fields, and environment scope only from an explicit artifact field; otherwise they remain `null`/`unknown`.

Missing local repositories are recorded in `pending_repositories` with `not-scanned` status. Missing numbers, failures, partial results, and skipped outcomes remain missing or preserved in the source; this catalog never fabricates them. Review secrets before public reuse, and keep every legacy artifact in its original location and format.

Discovery excludes non-evidence artifacts: `.github/ISSUE_TEMPLATE/**`, workflow definitions under `.github/workflows/**` and `templates/workflows/**`, hidden dotfiles, paths under any `fixtures/` or `testdata/` directory, and application source files identified by `src/**` or common language source extensions. A workflow's committed output can still qualify when it is stored outside the workflow definition path; the instrument itself does not. Synthetic compliance fixtures and UI/source files are excluded because they do not record historical measurements.
